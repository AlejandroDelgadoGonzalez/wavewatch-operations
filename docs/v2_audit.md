# V2 repository audit and migration decisions

## Preserved source material

The audit covered `rotation_calculator.py`, `park_data.py`, all four existing operational documents, both Python test modules, synthetic data assets, SQL/Drizzle scaffolding, frontend, styling, build/hosting configuration and SSR tests. Baseline verification passed 11 Python tests, the production build and 2 SSR/data tests before implementation.

- Python already implements all four closing-time break matrices, 15-minute transitions, delay adjustment, final bumps and the inclusive 30-minute closing cutoff. It remains unchanged.
- The JSON dataset remains the sole roster/attraction/stand source: 74 people, 68 rotation members, 17 rotations, 12 attractions, 4 zones. Existing data files remain unchanged.
- `db/schema.ts` has no operational schema; `examples/d1` is optional starter material. There is no persistent operating-day model to migrate. V2 keeps dynamic state in memory and retains optional database scaffolding.
- V1 used presentation-generated positions/times rather than consuming an event-driven day. V2 replaces those presentation assumptions with selectors over projected state.
- SSR assertions describing V1 presentation were updated for V2, preserving rendering and dataset coverage. No Python regression tests were removed.
- Work began on `codex/wavewatch-v2`, preserving V1 commit `46e5710beefaaed86bf4bdd6b6fed9fe0a4588fd` on `main`.

## Ambiguities resolved conservatively

| Question | Implementation decision |
| --- | --- |
| General shift-length language vs. explicit matrices | Use existing Python matrices and tests, not a competing duration formula. |
| Roster names vs. Avery/Blake/Cameron/Dakota test names | Map aliases by arrival slot only in tests/explanations; preserve the dataset. |
| Movement starts at 11:00, first break recorded at 11:10 | Show handoff at 11:00; update simultaneous assignment estimates at the recorded 11:10 start. No fabricated completion sensor. |
| No second-break end record | Calculate from observed start plus duration; label Calculated. |
| Delay based on calculated second-break end | Use estimated-delay language. Recorded first-break endpoints support detection, not attribution of fault. |
| Final/post-break movement is verbal, not recorded | Expected assignment projections, never Confirmed completion records. |
| Selected closing differs from fixed reference dataset | Use selected Python break matrix and closing + 30 for shifts; ignore stale reference-day break totals. |
| Coordinator breaks/extraordinary events lack rules | Show unmodeled plans and feed-only experimental notes. No automatic resolution. |

## Build and type safety

The inherited build passed, but standalone TypeScript checking exposed missing Cloudflare runtime declarations. These are now generated by installed Wrangler; an optional D1 binding is explicitly typed. Build artifacts, caches and browser output are ignored. Lockfile root metadata is aligned with the renamed V2 package.

No employer integration, proprietary information, paid service, external database, or deployment was added for V2.

## Compiled preview issue found in browser QA

The inherited `vinext start` rendered HTML but returned 404 for JavaScript/CSS on Windows. Inspection of installed `vinext/dist/server/static-file-cache.js` showed cache keys built from `path.relative` without normalizing backslashes to URL slashes. Browser QA caught this because the clock could not start. `npm start` now uses the existing Wrangler local Worker runtime and generated build config, preserving deployment compatibility without modifying dependencies. Development remains `npm run dev`.
